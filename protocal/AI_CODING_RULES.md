# AI 写代码规则（Protocol）

本规则用于约束 AI 在本项目中的编码行为，目标是保证一致性、可审计性与可复现性。

## 1. 先理解再修改
- 先阅读相关代码与文档，再做结构性修改。
- 避免凭假设重构；必要时先提出澄清问题。

## 2. 单一职责与边界
- 模块职责清晰，避免跨层耦合。
- Cognition 只做决策，不做执行。
- LLM 仅作为工具，不绑定业务语义。

## 3. 变更可追踪
- 每次新增/修改功能，必须更新 `history/STATE.md`。
- 对外行为变化要在说明中写清楚原因与影响。

## 4. 结构先于实现
- 先保证接口与数据结构稳定，再做实现细节优化。
- 需要扩展时优先新增模块/trait，而非破坏旧结构。

## 5. 错误处理统一
- 所有 crate 的错误类型统一走 `agent-error`。
- 不能抛出裸字符串或自定义散乱错误类型。

## 6. Prompt 与消息构建
- Prompt 必须保存在 `prompts/` 目录，禁止硬编码在 Rust 代码中。
- Prompt 渲染必须通过 `agent-utils`。
- LLM messages 通过 `agent-utils::MessageBuilder` 生成。

## 7. 日志与可观测性
- 关键错误必须记录日志（使用 `agent-utils` 的日志宏）。
- 日志应包含可定位信息，便于审计与回溯。

## 8. 允许失败但要明确
- 当信息不足时，允许输出 `NoAction`。
- 严禁编造缺失事实（禁止 hallucination）。

## 9. 示例可运行
- Example 代码必须可运行，且能说明模块用途。
- 示例必须反映当前真实结构，不得过期。

## 10. 清理与一致性
- 删除无用代码/占位结构（如无实际用途的默认构造器）。
- 保持依赖统一使用 workspace 配置。
